# SceneWorkbench interaction contract

The audience is zh-TW environment artists working with local Unity projects. Japan-market workflows do not apply. The complete product requirements remain in `docs/APPROVED_PLAN.zh-TW.md`; the development surface implements offline scene fields, source geometry/texture preview and native material property editing. Browser project paths and asset names remain local and are not uploaded.

## Canonical UI Map

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |

## Workflow and state

- The Open Project dialog defaults to Use project copy, creating and opening the specified new in-workspace destination. Unchecking explicitly selects direct read/write of the chosen project, shows a concise in-place-save explanation and hides the copy destination. Mode and actual project path remain visible in the workbench. No new recurring confirmation is introduced. Opening direct mode itself creates no metadata or native changes; only a real save lazily creates a transaction store, backing up changed files. Both modes retain identical version/schema, GUID/path, conflict, locking and recovery protections. Existing inspect API behavior remains for compatibility. The original D: template is never a development write-test target.

- Offline baseline preparation creates a separate complete copy and records the original Editor, explicitly chosen target, pinned package inputs and transaction backup. It does not launch Unity, migrate assets or certify native import. The default Client entry prefers the completed 2022.3.13f1 baseline when present; explicit startup sample configuration requires an in-workspace complete work copy. Existing open/edit/save/reload behavior remains available on the supported 2021.3 and 2022.3 stable profiles, bounded by the actual YAML schema. Unknown versions, linked objects and Material Variants remain read-only.

- Local HTTP service binds only to 127.0.0.1. Same-origin checks, exact Host checks, per-launch API token and no cross-origin permission protect filesystem APIs. The service serves only its UI directory; source assets require a validated project-relative API path. Private package URLs are not exposed.
- The legacy inspect mode opens original projects read-only. Explicit direct mode and verified WorkCopy mode share the same save protections. Creating a working copy requires a new destination; never overwrite a folder. The reference D: project is not used for test writes.
- Open project → choose `.unity` scene → select a standalone GameObject → edit known scalar fields → save the original `.unity` → reload. Saving stays on the same scene and selection, with a visible saved/dirty state. No-op save does not rewrite files.
- Scene selection loads automatically. The adjacent Load Scene button can explicitly load or retry the selected scene, including the already selected entry. The scene status row distinguishes native object loading, source preview loading, ready, partial preview and failed states; preview failure never announces complete success. Existing unsaved navigation protection applies to both triggers. Automated acceptance uses a separate local service so its long validation never reserves the interactive 5286 session.
- Scene loading shows a native progress bar in the viewport. It remains indeterminate unless the current GUID-index stage supplies valid current/total counts; displayed percentages refer only to that stage. It closes on success or failure. A failed first load retains its error and selected path even without an existing scene; changing projects clears the old scene state and progress. No guessed overall percentage or elapsed-time estimate is displayed.
- Each property edit uses C# command history. Undo/Redo is per property. IDs cross JSON as decimal strings to preserve signed 64-bit fileIDs. One session is shared by tabs; revision checks reject stale edits rather than overwriting them.
- Scene tools use Q (view), W (move), E (rotate), R (scale), with matching labelled buttons. A completed changed drag submits one existing position/rotation/scale command; ordinary orbiting, tool/space/snap changes and unchanged clicks create no history. Unity quaternion conversion mirrors preview Z consistently. Rotation stays a native quaternion; no Euler hint is rewritten. Scale is explicitly local; move/rotate remember world/local preference. Native select presets control translation units, rotation degrees and scale increments, without guessing project units are meters. Escape, pointer cancellation and lost window focus restore the in-flight preview without submitting it. Busy operations, Inspector drafts, material documents, unsupported fields, read-only objects and noninvertible parent transforms prevent dragging. Numeric Inspector fields remain the non-drag alternative. This does not enable Prefab overrides, parenting, multi-selection or new native schemas.
- Unsupported schemas, connected Prefab edits, RectTransform and unknown data remain read-only and preserved. Runtime version conflicts remain visible; only enumerated GameObject/Transform and native Material saved-property capabilities may save under the two runtime-only mismatch codes. No general force-write option exists.
- Inspector draft validation precedes server changes. Invalid values remain visible and focus moves to the failing field. No partially validated request changes the document. Selecting another item commits a valid draft; an invalid draft prevents selection change.
- Scene/project navigation with unsaved work offers Save, Discard and Cancel in the shared dialog. Initial focus is Cancel. Escape cancels and focus returns to the trigger. Browser unload alone uses the browser lifecycle warning.
- File/meta/settings conflicts retain the current edit, show a persistent explanation and offer reload with the unsaved-work dialog. No automatic overwrite. Interrupted saves use the existing transaction recovery, followed by scene reload.
- Async work reserves a status row, disables duplicate operations, exposes progress and cancellation where the core supports it. Errors preserve the current document and inputs. A network/session failure never clears a draft or claims it saved.
- Hierarchy and Project own independent search with immediate clear and focus return. Local filtering is immediate; remote search is debounced 300ms, cancels prior requests, and ignores stale responses. IME composition never triggers submit or shortcuts. Queries are transient per local project and intentionally excluded from URLs to keep local asset names private.
- Long result sets use explicit Load more. Empty, no-results and error states keep a stable panel footprint and offer a relevant next action.
- Opening loads source assets and scene paths without recursively indexing the package cache. Package folders remain directly browsable. The first global search builds the complete catalog with request cancellation, atomically replacing it only after success; failure or cancellation leaves it retryable. `packageCacheIndexed` indicates completeness, and `sourceFiles` is the currently indexed count. Opening another project resets the catalog. Native save validation continues to inspect its full required scope.
- Project `.mat` selection or a Renderer material link opens Material Inspector. Scene and material are separate active native documents; switching with unsaved work uses the same Save/Discard/Cancel contract. The shared toolbar's Save, Undo and Redo operate on the active document. No multi-file partial save is presented as an atomic document save.
- Material Float/Range/Color/Vector values use Float32 validation. True `m_Ints` uses an exact Int32 path through JSON, commands, native scalar patches and snapshots. Legacy ShaderLab Int stored in `m_Floats` rejects integers that Float32 cannot represent exactly. The Inspector identifies this distinction, with numeric alternatives for vectors/colors and explicit source texture paths with Project drag/drop. All edits in one Apply request validate before the first live command. Each property remains its own Undo step. Number drafts preview on the material ball; texture assignments preview after Apply. Keywords, unsupported texture dimensions and absent saved entries stay read-only. Save writes `.mat`; it preserves attached Unity objects, Shader/ASE data, GUID/meta and other saved properties.
- Material conflicts cover native content, meta, source Shader, referenced textures and project version/dependency settings. Save still runs the complete asset/GUID validation. Invalid or stale requests retain the local draft and offer Restore/Sync/Reload through existing controls.
- Source FBX and Mesh asset inspection has a shared orbitable geometry viewport; source PNG/JPEG/WebP/TGA/BMP can be inspected. Source geometry inspection does not infer a scene's material assignments. Mesh/FBX data, Rig and animation remain unmodified. Unsupported models/identities produce a diagnostic.
- A derived preview GUID cache lives under workspace `artifacts/cache/preview-guid`, validated against the current metadata/file inventory. It never replaces native-save validation; cancellation cannot publish a partial cache. Scene reload recreates the resolver so external metadata edits are checked. The original project remains read-only.
- The status region and Console share terminology and diagnostics. Fixed ASE adapters are tied to exact source hashes; edited Shader code requires revalidation and displays warning geometry. Inspector states the effects not yet matched. Collision-helper visibility and preview time change only the view. No ASE/URP fidelity or Unity engine roundtrip claim is made.
- Current graph diagnostics stay in Console ahead of the capped transient asset log and contribute to its count. Reload replaces them; changing projects/scenes clears the prior graph's diagnostics. Asset loading cannot silently evict an unresolved Prefab target.
- Cancelling an active transform gesture takes precedence over the text-field shortcut guard, while IME composition and modal dialogs retain ownership. Cancellation restores the object's full transform, clears the pending orbit interaction through the public OrbitControls lifecycle, and creates no scene command. A bounded passive viewport DOM trace records the last gesture and trusted-event metadata for verification; it cannot submit input or edit data. Native changed-drag Escape, later release, unchanged camera and unchanged history have actual browser evidence; focus loss, visibility loss and pointercancel still have unit coverage only.

- Direct FBX preview reads explicit native material slots, Renderer enabled state and unique Transform overrides, including an outer Prefab override mapped through its exact stripped instance correspondence. The material GUID must resolve uniquely and its signed fileID must match the actual native Material object. Browser preview additionally requires exactly one decoded Mesh and one native Renderer override; ambiguity retains source geometry and a diagnostic without assigning guessed materials or transforms. This does not certify Unity's imported FBX hierarchy or full Prefab editing.
- Nested Prefab target routing first uses explicit stripped correspondence. For supported 2021.3/2022.3 version-2 FBX instances only, a missing virtual stub may use the XOR63 identity rule when every explicit anchor of that exact instance proves it, the source ID already has an unambiguous native role, and the target is globally unique within that Prefab scope. Order remains native last-write-wins. Missing/colliding anchors reject; names and list positions never identify an object. The graph exposes target-level resolution details. A removal targeting a component absent from a complete non-nested source is preserved as an unused removal; uncertain removal targets and unresolved property overrides remain explicit diagnostics. This is read-only preview routing and does not open native Prefab writers or certify engine behavior.
- Mesh construction must provide a material for every referenced preview group so rendering and picking use the same complete surface. Primitive face groups generated by the preview are not native Unity slots. Genuine decoded submesh bounds and explicit source assignments stay intact; missing slots use labelled diagnostic materials. An ungrouped surface uses its first slot, retaining extra native references and an explicit limitation for unpreviewed extra passes. Invalid group indices reject safely. This never rewrites native Mesh, Renderer or Material data.
- When Shader source is unavailable, saved native texture identities, numeric values and colors remain visible but read-only. Recognized main textures can provide an explicitly labelled surface approximation. StylizedWater2 pins the `.watershader` template and eleven HLSL libraries; its adapter uses actual opaque scene depth, native colors, waves, sharp intersections, distance normals, horizon and translucency. Actual keywords govern enabled effects, and zero wave speed/normal strength stay zero. Map_60001 disables surface foam, refraction and caustics. Default environment reflection requires an exact matching-scene LightingData PPtr, one baked cube with no local probes, supported cubemap importer/EXR layout and unchanged source hash. Never select a reflection image by filename or substitute another sky. Water shadows follow the active native directional light, strength, renderer receive flag, Layer/culling/rendering masks and caster flags; cutout caster textures keep their native cutoff and tiling. Terrain's explicit shadow-off stays off. Full GI/CSM/Shadowmask/local probe blending remain unmatched. The material ball explicitly lacks scene depth/shadows. Native Shader, Material and LightingData stay read-only; changed/missing template/library identities produce diagnostics. Neither approximation nor a valid source binding grants native writing capability.

- Terrain 218 preview resolves the exact TerrainData GUID/fileID, reads supported 2021.3/2022.3 binary type trees, decodes the complete SInt16 height grid and native scale, and respects Terrain enabled/DrawHeightmap and ancestor visibility/transforms. RGBA32 control weights and exact TerrainLayer Diffuse/Tiling provide a labelled surface approximation. A missing layer keeps its GUID and explicit checker diagnostic. Nonempty unsupported holes retain metadata but prevent rendering an assumed solid surface. Invalid/missing samples produce diagnostics rather than fabricated ground. Terrain Inspector values remain read-only; this does not enable TerrainData writing, sculpting, physics or complete URP Terrain Lit.

## Input, layout and accessibility

Use real buttons, associated labels, native selects, `<dialog>` with showModal focus isolation, visible focus and text with every semantic color. All edits have numeric/form alternatives to dragging. Search and command handlers ignore composition. Ctrl+S saves; Ctrl+Z/Y operate scene history only outside text fields; F focuses a selected scene object only in the viewport. Keyboard commands have visible button alternatives.

Desktop panels scroll independently; narrow screens stack and scroll naturally. Inspector actions remain in normal document flow below 900px, with all coordinate inputs directly clickable; desktop sticky actions are scoped to the Inspector scroller. Persistent errors wrap; path tooltips and selectable full text expose truncated labels. System fonts eliminate font-swap shifts. Reduced motion disables decorative transitions. Forced colors restore system colors and scrollbars. Full screen-reader, touch and 200% zoom certification are separate acceptance gaps until measured.
