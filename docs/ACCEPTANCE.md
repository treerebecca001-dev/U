# 階段 0／1 工具交驗

本文件原有 CLI 交驗流程保留為歷史紀錄。2026-10-22 最新人類指示是原始碼啟動的本機網頁開發版，**不要打包**；目前請依 `HANDOFF_WEB_DEV_20261022.md` 驗收，不執行下方舊 publish 命令。網頁有限欄位能力、嚴格 CLI gate 及完整 Unity 互通各自判定，不互相擴大宣稱。

## 本次可單獨驗收的宣稱

正常操作的必要條件是：不需安裝、啟動或授權 Unity，也不呼叫背景 Unity 轉檔服務。獨立執行與 Unity 原生互通分別保留證據；缺少 Unity 的外部驗收不等同獨立程式必須停工，但也不能視為已通過互通驗收。

1. 讀取專案並正確標示版本／套件衝突、GUID、場景與 Shader 盤點。
2. 建立完整 Unity 來源工作複本，保留 GUID、逐檔雜湊、空資料夾及套件快取。
3. 來源專案不可寫；禁止重疊目的地、路徑逃逸與 junction／symlink。
4. 局部 YAML 修改保留 BOM、換行、未知元件及其他物件；Undo 回復原始位元組。
5. 外部修改阻擋覆蓋；中斷存檔可復原；復原不覆蓋新外部修改。
6. 實際 CLI 可建立複本、預覽修改、儲存、重新讀取，並拒絕回寫版本衝突專案。
7. 容器重寫報告區分本機欄位比對、Unity 載入及新烘焙生成三種證據。

## 重現

```powershell
.\scripts\bootstrap.ps1 -Restore
.\scripts\verify.ps1
.\scripts\publish.ps1
.\scripts\verify.ps1 -CliExecutable '<新發佈資料夾>\SceneWorkbench.exe'
```

測試記錄保留在 `artifacts/logs` 與 `artifacts/test-results`。與 junction 有關的隔離測試樣本會保留在 `artifacts/test-runs`，避免測試清理遞迴刪除連結。測試樣本不代表 Unity 已載入驗證的場景。

發佈資料夾內的 `build-manifest.json` 固定各檔案 SHA-256。驗收報告應記錄使用的 manifest、命令、退出碼、結果檔與已知缺口。

## 完整計畫仍須另外通過

Unity 2021.3.15f1／URP 14.0.9 的基準仍需建立有效、可重現的驗證環境。不能只改版本字串、跳過檢查或假設 Unity 已載入成功。

階段 1 必須包含獨立產生新原生資料，並取得 Unity 原系統載入與繼續編輯證據。YAML 本機測試、資源原樣複製、容器重寫、成功建置和單元測試數量，均不能替代此驗收。

UI、Shader、Play、地形製作、建模、粒子、雙套尋路與完整光照烘焙，應逐項標示未實作／未驗證，不將本次工具的通過擴大為完整產品通過。

完整產品的獨立驗收須在未安裝 Unity 的乾淨環境執行，包含開啟、編輯、存檔、重新讀取、預覽 Play、尋路及光照生成。開發機曾安裝 Unity 或僅未啟動 Editor 的本機測試，不能冒充這項乾淨環境驗收。Unity 端驗收由另外可用的合法環境進行，不要求目前的使用者啟用授權。
